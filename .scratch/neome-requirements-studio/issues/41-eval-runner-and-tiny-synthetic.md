  - The replay driver is code, not an LLM session: the 6 user skills are `disable-model-invocation`, so a driving agent cannot call them; each skill step is its own headless session (also keeps one Module per session).   - Simulated client = one tool-less `claude -p` session per step (`--tools ""`, `--system-prompt` = client prompt + cast + answer key, nothing else), cwd outside the clones. It returns structured answers (`keys`, `dontKnow`, `as`) so the log knows every Don't know; the judge maps each to an Open Item; new hard gate `dontKnow` = 0 (Consultant-role answers excluded).
  - Case gets a 5th file `replay.yaml` (steps + per-step brief) and `golden.json` gets optional `mechanics` (deterministic end-state checks: file, text, oi, gen, version, changes, modules, git). Failed mechanics and replay problems (turn limit, engine step exit, unusable client answer) are hard gates (0); both rows in the README Thresholds table with reasons.
  - Thresholds single source = `evals/README.md` Thresholds table; runner parses it, fails if a row is missing.
  - "Last result on `main`": each result's Data block records the repo branch at prepare (`--branch` override); baseline = newest result of that case with branch `main`; none → no regression check. Same-day rerun → `-2`, `-3`.
  - Golden `sources` name case Input files or K-NN (Source IDs exist only after ingest); golden OIs carry free-text `answeredBy` so the judge can credit "answered correctly in a Requirement".
  - Recall counts GEN Requirements. Mapping metric: hit when every matched replay Module carries the golden Delivery; n/a when golden has no mapping.
